## §3 End-to-End Workflow: Storage Organisation and Small-Scale Validation Subset

### 3.1 Data Directory and Run Storage Layout (Decision D20)
ContextGuard strictly decouples code, configuration, datasets, and runtime artifacts to ensure reproducibility across machines:
- **`data/` (Data Store):** All datasets are organized hierarchically. In accordance with course guidelines and data governance rules, raw benchmarks, processed ground-truth files, partitioned splits, and validation subsets are excluded from version control via `.gitignore`. A versioned minimal sample (`data/sample/m2_examples_sample.jsonl`) is tracked to verify pipeline interfaces on clean clones.
- **`outputs/runs/<run_id>/` (Run Records):** Every execution (such as `m3_smoke`) writes its runtime state into an isolated folder under `outputs/runs/<run_id>/`. This directory encapsulates:
  1. `config.yaml`: Frozen snapshot of all model, training, and inference parameters.
  2. `versions.json`: Pinned library and environment versions.
  3. `seed`: The integer random seed used for reproducibility.
  4. `rules.json`: Proposed and verified Stage 0 (D7) rules.
  5. `candidates.csv`: Candidate cell flags generated by detectors D1–D6 and D7.
  6. `predictions.jsonl`: Raw and validated model responses per cell.
  7. `metrics_by_table_type.csv`: Computed evaluation scores across tables and error types.

### 3.2 Small-Scale Validation Subset (Decision D17)
To enable fast iteration and complete end-to-end pipeline verification without incurring large GPU and inference overheads, `src/data/make_subset.py` constructs a lightweight, representative subset of the validation split:
- **Scope & Isolation:** Drawn exclusively from the validation splits (`val.csv`, `val_clean.csv`, `val_cells.csv`) of three core benchmark tables: **Hospital**, **Flights**, and **Beers**. The test splits and unseen benchmark tables are strictly untouched.
- **Sampling Protocol:** Samples exactly **100 rows per table** using a fixed random seed (`seed = 42`). Crucially, all cells across all columns of these 100 rows are preserved in full (19 data columns for Hospital, 6 for Flights, 10 for Beers). This ensures downstream detectors and the fine-tuned LLM encounter real-world, natural error rates rather than artificial subsamples.
- **Positional Re-indexing:** In `val_cells.csv`, row coordinates are re-indexed to `0..99` to ensure exact 1:1 positional alignment with `dirty.iloc[row]`.

## §6 Model Inputs and Outputs: Training Data Loader and Collation

### 6.1 Chat Template Formatting and Tokenisation
ContextGuard leverages the instruction-tuned **Gemma 4 E4B-it** architecture. Training inputs must adhere strictly to the canonical Gemma multi-turn chat template:
```text
<start_of_turn>user
{prompt}<end_of_turn>
<start_of_turn>assistant
{response}<end_of_turn>
```
The prompt encapsulates cell-level profiling: the target row, column summary, dependency evidence, and nearest-neighbour rows from the dirty table. The response is a single structured JSON object containing `is_error`, `error_type`, `evidence`, and `repair`.

### 6.2 Label Masking for Supervised Fine-Tuning (Decision D14)
Standard causal language modelling computes cross-entropy loss over every token in the sequence. In instruction fine-tuning, calculating loss on prompt tokens is counterproductive: the model should not be penalized for reproducing context that was provided in the prompt.
- In `src/llm/dataset.py`, `ExampleDataset` tokenises the prompt (including the assistant turn header `<start_of_turn>assistant\n`) and the assistant response separately to locate the exact transition boundary.
- **Decision D14 Implementation:** All prompt tokens and turn markers up to the opening character of the JSON response are assigned a label of `-100` (`torch.nn.CrossEntropyLoss(ignore_index=-100)`).
- Only the assistant response tokens (and trailing turn-end tokens) retain their true token IDs. Cross-entropy loss is therefore evaluated strictly on the model's generated answer.

### 6.3 Batch Collation and Padding (Decision D13)
The custom `collate(batch, pad_token_id=0)` function processes variable-length sequences within each micro-batch:
- Finds the maximum sequence length in the current batch ($L_{\text{batch}} \le 1536$).
- Right-pads `input_ids` with `pad_token_id` (default `0`).
- Right-pads `attention_mask` with `0` (active tokens receive `1`).
- Right-pads `labels` with `-100` so padding tokens never contribute to training loss.
- Returns 2D PyTorch tensors of shape `[batch_size, L_batch]` with dtype `torch.int64`.

## §14 Risks and Limitations (Data Loader and Subset Modules)

1. **Risk of Truncation of Assistant Answers:**
   - *Risk:* If sequence lengths exceed the maximum token budget (`max_len = 1536`), naive right-truncation cuts off the closing brackets of the assistant's JSON output, leading to unparseable responses during training and validation.
   - *Mitigation:* We audited all 64,432 examples across `train.jsonl` and `val.jsonl`. The longest sequence encountered is 1,020 tokens, leaving an ample safety margin of over 500 tokens. Zero examples exceed 1,536 tokens.
2. **Sampling Variance in Small-Scale Subsets:**
   - *Risk:* A sample of 100 validation rows per table might inadvertently under-sample rare error types (such as numerical outliers or localized functional dependency violations).
   - *Mitigation:* As proven in Table 3.1, the overall error rates of the 100-row subsets deviate from the full validation splits by only $-0.04\%$ (Hospital), $+1.03\%$ (Flights), and $+0.29\%$ (Beers). All primary defect categories (missing values, pattern violations, and rule violations) are well-represented.
3. **Batch Padding Inefficiency:**
   - *Risk:* Padding all batches to a static length of 1,536 tokens would waste computational throughput on redundant `-100` masked tokens.
   - *Mitigation:* The `collate` implementation uses dynamic micro-batch padding, determining $L_{\text{batch}}$ based strictly on the longest item in that specific batch.

```python
class ExampleDataset(torch.utils.data.Dataset):
    """
    Args:
        path (Union[str, Path]): Path to .jsonl file with instruction-response records.
        tokenizer (Any): HuggingFace AutoTokenizer or compatible object.
        max_len (int): Maximum sequence token budget (default: 1536).
    Returns:
        Dict[str, torch.Tensor]:
            - 'input_ids': 1D Tensor of int64 token IDs, length <= max_len.
            - 'attention_mask': 1D Tensor of int64 ones, length <= max_len.
            - 'labels': 1D Tensor of int64 where prompt tokens are masked to -100.
    """

def collate(batch: List[Dict[str, torch.Tensor]], pad_token_id: int = 0) -> Dict[str, torch.Tensor]:
    """
    Right-pads a list of single-example dictionaries into batch tensors.
    Args:
        batch: List of dictionaries returned by ExampleDataset[i].
        pad_token_id: Token ID used to pad input_ids (default: 0).
    Returns:
        Dict[str, torch.Tensor]:
            - 'input_ids': 2D Tensor [batch_size, max_batch_seq_len] (torch.int64).
            - 'attention_mask': 2D Tensor [batch_size, max_batch_seq_len] (torch.int64).
            - 'labels': 2D Tensor [batch_size, max_batch_seq_len] (torch.int64) with -100 padding.
    """
```
